# 懸賞応募アシスト（公開版）

ログイン不要の静的PWA。応募状況とお気に入りはブラウザのlocalStorageだけに保存します。応募は公式サイトで利用者が行います。

**公開URL:** https://ginji001.github.io/kensho-public/

## 公開状態

- GitHub PagesでHTTPS公開済み
- Windows / MacのBraveで実画面確認済み
- manifest / Service Worker / オフライン再表示を自動確認済み
- 公開データに内部ネットワークURLや認証付きURLが混入していないか、Pages配信前に自動検査

## 実装済み

- キーワード・ジャンル・掲載元・優先度・応募状態・締切・当選人数・条件・賞品タイプで絞り込み
- おすすめ・当選人数・締切・新着・条件の軽さ順
- 応募済み／条件待ち／見送り／お気に入りの端末内保存
- 日本時間の期限判定、明示時刻の期限にも対応
- HTTPSの許可ドメインのみ、内部IP・認証付きURL・秘密値を含むURLを拒否
- manifest、192/512 PNG、Service Workerによるオフライン一覧
- 6時間ごとのGitHub Actionsによる登録済みリンク確認・期限処理・Pages再配信
- 公開ファイルは public/ のみ。個人用APIや個人版ファイルは一切接続しません

## 実行

Node.js 22以上。依存パッケージ不要。

```sh
npm test
npm run refresh
npm run build
npm start
```

GitHub Settings → Pages → Sourceを **GitHub Actions** に設定すると、main更新またはActions手動実行で配信します。スケジュール実行はGitHubの都合で遅れる場合があります。

## 管理と更新

認証されたGitHubの編集画面／Pull Requestを管理面として利用し、公開側には管理APIを置きません。

1. `data/reviewed-campaigns.json`で公式確認済みの案件を追加・修正します。
2. 新しい公式ドメインは `data/source-policy.json`のallowedDomainsに登録します。
3. 非表示は `hidden: true`、優先度手動補正は `priorityOverride`で指定します。
4. テストと検証を通したmainを公開します。緊急時はGitHub Pages設定で配信停止できます。
5. Actionsのlink-reportに確認結果が残ります。HTTPエラーや未承認の転送先は「リンク確認中」にし、検索ページへ転送しません。

氏名・住所・電話番号・メール・Cookie・セッショントークン・個人の応募履歴をこのリポジトリに追加しないでください。公開JSON生成はフィールドを限定し、URLも検査します。応募者の状態のエクスポートや同期は提供しません。

## 未完了と制約

**指示書の全完成条件を満たす段階ではありません。**

- 新規案件の自動発見・取り込みは未接続です。`source-policy.json`のdiscoveryは計画用であり、収集実行機能ではありません。規約・再配信条件の確認を経て収集アダプターを追加する必要があります。現在の定期実行は登録済み案件のリンク検証・期限処理です。
- LIPSは自動アクセスしません。管理者による公式画面確認後、`manualVerifiedAt`に確認日時を記録すると48時間だけ入口を有効化します。日時の追記だけで確認済みと扱わず、必ず内容・期限・リンクを実確認してください。
- 初期候補は個人版の公開項目から抽出。文字化け・条件不明の行は除外しました。全案件の賞品・条件・無料区分の独立照合は未完了です。未確認の無料・購入不要を推測しません。
- 公式本文の終了表記検出には限界があります。先着・応募規約・締切時刻は公式情報を優先してください。
- iPhone / Androidの実機インストール、ホーム画面起動の最終確認は未完了です。
- 個人版には変更していません。開発中に健康確認APIの正常応答のみ確認しました。

## プライバシー

本サービスは応募先サイトの入力情報を収集・保存しません。応募は各公式サイトで行われます。配信サービス自身のアクセスログはその事業者のポリシーによります。ブラウザデータを削除すると応募状態も失われ、端末間同期はありません。
